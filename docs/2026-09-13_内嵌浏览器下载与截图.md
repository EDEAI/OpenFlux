# 内嵌浏览器（右侧栏）下载与截图

**创建时间：** 2026-09-13
**状态：** 已实现（Windows），本地 dev 端到端验证见文末
**相关文档：** [插件页与技能插件中心](2026-09-13_插件页与技能插件中心.md)

## 1. 背景

右侧栏浏览器是 Tauri 子 webview（Windows = WebView2，macOS = WKWebView），Agent 通过 `browser_control` 工具驱动。此前它只有"看、点、读 DOM"的能力：页面触发下载时文件落到系统默认下载目录并弹 WebView2 自己的下载条，Agent 完全不知道；也没有截图动作，只能靠文本快照。本次补齐这两项，先做 Windows。

## 2. 下载

链路：`WebviewBuilder.on_download`（Rust）→ `browser-view:download` 事件 → 面板记录 → `downloads` op → `browser_control` 的 `downloads` 动作。

| 环节 | 文件 | 说明 |
|---|---|---|
| 目录配置 | `src-tauri/src/commands/browser_view.rs` `browser_view_set_download_dir` | 全局 `DOWNLOAD_DIR`；空字符串恢复引擎默认目录。gateway 每次执行 `browser_control` 前通过面板 `config` op 下发 `<outputPath>/downloads`（只在路径变化时发一次） |
| 重定向与去重 | 同上 `on_download` / `unique_target` | 保留引擎建议的文件名（Content-Disposition / URL），同名追加 ` (1)`、` (2)`。装了 handler 后 wry 会 `SetHandled(true)`，WebView2 自己的下载条不再弹出 |
| 事件 | `DownloadPayload { label, url, path, kind: started/finished, success }` | 面板按 label 过滤 |
| 面板记录 | `src/panel/browser-pane.ts` `onDownload` / `listDownloads` | 每个标签最多保留 50 条；状态栏显示「正在下载 / 已下载 / 下载失败」；`downloads` op 支持 `clear` |
| Agent 动作 | `gateway/src/tools/browser-control/index.ts` `downloads` | `wait=true` 轮询到没有进行中的下载（`timeoutSeconds` 默认 60，最大 300），返回文件名、状态、耗时、完整路径和来源 URL，并提示用文件工具读取 |

`on_download` 在 wry 里 Windows 和 macOS（WKDownload）都有实现，所以 macOS 理论上也能收到事件，但没有验证。

## 3. 截图

`browser_control` 新增 `screenshot` 动作，走面板已有的 `cdp` op 调 `Page.captureScreenshot`：

- 默认视口；`fullPage=true` 用 `Page.getLayoutMetrics` 取内容尺寸做 clip（高度封顶 16384）；`ref=N` / `text` 只截某个元素（用最近一次 snapshot 的元素框）。
- PNG 保存到 `<outputPath>/browser-screenshots/<时间戳>-<tab>.png`，可用 `path` 参数指定（相对路径相对 outputPath）。
- 返回的 `images` 会作为视觉输入喂给模型（不设置 `imagesForDisplayOnly`），所以模型能真的"看"到页面；文本里附带保存路径。
- macOS 的面板桥只支持脚本求值，`Page.captureScreenshot` 会失败，返回明确的错误提示改用 snapshot / get_html。后续可用 WKWebView 的 `takeSnapshot` 补。

## 6. 附带修正：Agent 看图的正当渠道（同日）

remotion 任务日志暴露的问题：Agent 为目检视频帧借用了 `inspect_presentation_references`，其返回里无条件带着 `nextAction: "…pass it into generate_presentation…"`，模型照做，误启了演示文稿状态机（10 次多余调用、留下无用 PPT）。两处修正：

- `gateway/src/tools/file-reader/index.ts`：支持 png/jpg/jpeg/webp/gif/bmp/tiff/svg/avif，用 sharp 缩到 1600px 内以 PNG 作为 `images` 返回给视觉模型，`data` 只给尺寸和一句"仅供查看"。这是看截图、视频帧、图表的正当渠道。
- `gateway/src/tools/presentation/references.ts`：新增 `purpose` 参数（design_reference / inspect）。未指定时，只给了图片就按 inspect 处理，不再返回 nextAction，改为"仅供查看，未启动演示文稿工作流"的 note；给了 PPT/PDF 或显式 design_reference 才返回原来的 nextAction。工具描述也明确指出"只想看图请用 file_reader"。

验证：通过 WS `tool.call` 直接调用，file_reader 返回 480×860 的 PNG；references 无 purpose 时 `purpose=inspect` 无 nextAction，显式 design_reference 时恢复 nextAction。presentation 与 file-reader 单元测试通过。

## 7. 面板 UI：下载按钮与下载列表（同日）

- 地址栏不再占满工具栏：`flex: 0 1 320px`，最小 120px。
- 地址栏右侧新增下载按钮（`browser-pane-downloads-btn`）：角标显示进行中的下载数（脉动高亮）或历史条数；点击在工具栏与页面之间展开/收起下载列表（`browser-pane-downloads`）。列表是文档流内的元素而不是浮层，所以不会被原生子 webview 盖住，展开时 stage 变矮、webview 随 ResizeObserver 重新定位。
- 每条记录：文件名、状态（下载中/已完成/失败）、耗时、开始时间、完整路径；已完成的有「打开文件」（`file_open`）和「打开所在目录」（`file_reveal`）；表头有「清除记录」（保留进行中的）。
- 历史按 pane id 存在 localStorage（`openflux-browser-pane-downloads:<paneId>`，最多 50 条），标签挂起/重开和应用重启后仍在；重启前未完成的记录标为失败。Agent 的 `downloads` 动作读的是同一份数据。
- 验证：在测试会话的标签里直接打开 CSV 地址触发下载，角标变为 1，列表出现「report.csv 已完成 · 0.1s · 09:14 · D:\openflux_output\downloads\report.csv」，两个操作按钮可用，localStorage 中有 1 条记录。

## 8. 工具栏重排 + 历史记录 + Cookie（同日）

- 工具栏：左侧导航组（后退/前进/刷新），地址栏居中（`flex: 0 1 360px; margin: 0 auto`，未聚焦时文字居中），右侧工具组（历史 / Cookie / 下载）。三个按钮共用一个下拉面板 `browser-pane-panel`，同一按钮再点一次收起，点另一个切换模式。
- **历史记录**：所有浏览器标签共用一份，存 localStorage `openflux-browser-history`（最多 300 条）。页面 `readyState=complete` 且拿到标题时记录（`refreshTitle`），连续访问同一 URL 只更新时间和标题；跳过 about:blank 与 chrome-error。面板支持搜索（URL/标题子串）、点击跳转、清除。Agent 动作 `history`（`text` 过滤、`limit`），走面板 `history` op。
- **Cookie**：全部经现有 `cdp` op 调 Chromium DevTools 的 Network 域（Windows）：`Network.getCookies {urls:[当前页]}` 列表（名、值、域/路径、过期、HttpOnly/Secure），单条删除 `Network.deleteCookies`，「清除本站」逐条删，「清除全部」`Network.clearBrowserCookies`。macOS 上调用失败时显示"暂不支持"。Agent 动作：`cookies`（`name` 过滤、`raw` 全值）、`set_cookie`（name/value/domain|url/path/expiresInSeconds）、`delete_cookies`（name/domain 或 `all=true`，工具描述要求 all 需用户明确要求）。
- 验证：本地 cookies.html 写入 3 个 cookie 后面板列出 3 条（会话/带过期/长值截断），历史面板列出两个测试页并可搜索；Agent 侧 history/cookies/set_cookie/delete_cookies 走一轮真实对话验证（见下）。
