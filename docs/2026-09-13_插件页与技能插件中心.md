# 插件页与技能插件中心（Plugin Hub）

**创建时间：** 2026-09-13
**状态：** 已实现，本地 dev 环境验证通过（安装 / 卸载 / 视图切换）
**相关文档：** [ProcessPlugin 插件服务架构](architecture/2026-05-25_ProcessPlugin插件服务架构.md)、[Excel Plugin](2026-05-18_Excel-Plugin-Install-Uninstall.md)

## 1. 做了什么

1. 左侧栏「定时任务」下新增「插件」入口，点开后占据中间工作区（与定时任务页同级）。
2. 原侧栏「外部连接」分组里的四个开关（Excel / Word / PowerPoint / Chrome 录制扩展）迁到插件页的「本地插件」板块；侧栏该分组现在只剩 CLI Coding Agents 卡片（`data-feature="codingAgents"` 控制显示）。
3. 新增「技能插件」板块：静态技能插件包（agent-plugins-spec / Codex 插件格式）的安装中心。首批同步了 `hyperframes`、`remotion` 两个纯技能包。

## 2. 两套"插件"的区别

| | Plugin Protocol v1（既有） | 技能插件中心（本次新增） |
|---|---|---|
| 本质 | 运行时 WS 客户端进程向 Gateway 注册工具 | 静态目录：plugin.json + skills/<name>/SKILL.md |
| 例子 | Office 加载项、Chrome 扩展 | hyperframes、remotion |
| 生命周期 | 连上即存在，断开即消失 | 安装到 data/evolution/installed-plugins/<id>，启动时重新注入 |
| 注入方式 | 代理 Tool（isPlugin） | AgentManager.addSkill 一条"技能目录"（渐进式加载） |

## 3. 文件地图

| 文件 | 作用 |
|---|---|
| `scripts/sync-codex-plugins.mjs` | 从 openai/plugins 做 sparse clone，解析 plugin.json 与各 SKILL.md frontmatter（支持 `description: \|` 块标量），复制到镜像目录并生成 index.json；`--dist` 产出 tar.gz + sha256 供上传官网。许可证白名单过滤，>2MB 文件跳过 |
| `src-tauri/resources/plugin-hub/` | 内置镜像（index.json + plugins/<id>/），已加入 tauri.conf.json / tauri.macos.conf.json 的 resources |
| `gateway/src/plugins/hub.ts` | `PluginHub`：bundled 镜像（通过 OPENFLUX_RESOURCE_DIR 定位）∪ 远程镜像（默认 `https://openflux.io/plugins/index.json`，`OPENFLUX_PLUGIN_HUB_URL=''` 关闭）∪ 已安装；install / uninstall / loadInstalled；远程安装校验 sha256 后用系统 tar 解压 |
| `gateway/src/gateway/standalone.ts` | 创建 PluginHub、启动时 loadInstalled、WS 消息 `plugin.hub.list` / `plugin.hub.install` / `plugin.hub.uninstall` |
| `src/gateway-client.ts` | `listHubPlugins` / `installHubPlugin` / `uninstallHubPlugin` 与 `HubPlugin` 类型 |
| `src/plugins/view.ts` + `src/styles/plugins.css` | `PluginsPage`：本地插件卡片（开关复用原 handlers）+ 技能插件卡片（安装 / 卸载 / 更新、详情、示例提示词一键填入输入框） |
| `src/main.ts` | `buildLocalPluginDefs()`（原 appendConnectSection 的开关定义）、`appendCodingAgentSection()`（侧栏只剩 CLI 卡片）、`togglePluginsView` / `closePluginsView`、`pluginsPage` 初始化；所有关闭定时任务页的地方同步关闭插件页 |
| `../openflux-site/upload_plugin_hub.py` | 把 `--dist` 产物上传到 openflux.io `/plugins/`（先传归档再传 index.json） |

## 4. 技能注入策略

一个插件只注入一条 skill（id `plugin:<id>`），内容是技能目录：插件简介、根目录绝对路径、每个技能的名称 / 描述（截断 320 字）/ SKILL.md 绝对路径，并明确要求模型"匹配时先用 filesystem / file_reader 读 SKILL.md 再执行"。hyperframes 约 3KB、remotion 约 4KB，避免十几个 SKILL.md 全文撑爆 system prompt。这与 Codex 自身的按需加载一致。

## 5. 同步与发布流程

```
# 有 GitHub 访问的机器上
node scripts/sync-codex-plugins.mjs --dist ../openflux-site/plugin-hub-dist   # 更新内置镜像 + 产出上传物
cd ../openflux-site && set OPENFLUX_DEPLOY_PASSWORD=... && python upload_plugin_hub.py
```

客户端启动 / 打开插件页时先读远程 index.json（8s 超时，10 分钟缓存），远程条目版本更新则覆盖内置条目并显示「可更新」；远程不可达时回落到内置镜像。**远程下载路径尚未真机验证**（官网还没有上传过）。

## 6. 已知边界

- 只处理 skills；plugin.json 里的 mcpServers 只在目录里列出，不自动连接；apps / hooks 忽略。
- 技能正文里的 `$skill` / `@plugin` 提及语法未做解析。
- 技能里的脚本走 OpenFlux 自己的 process 工具与权限策略，不等价于 Codex 沙箱。

## 7. Figma 插件迁移 + 插件 MCP 接入（2026-09-13 晚）

**同步**：`sync-codex-plugins.mjs` 新增 `--allow-license`（figma 的 `LicenseRef-Figma-Developer-Terms` 已放进 `DEFAULT_ALLOW_LICENSES`，索引里带 `licenseNote`），文本类参考文件上限放宽到 12MB（figma 的 plugin-api .d.ts 靠 grep 按需读），并识别插件根目录的 `.mcp.json`（figma 的 manifest 没写 mcpServers）。figma@2.0.20：12 个技能、1 个 http MCP、apps 忽略，compat=partial。

**MCP 客户端**（`gateway/src/tools/mcp-client.ts`）：新增 `http`（Streamable HTTP）传输、`cwd`/`headers`/`bearerTokenEnvVar`/`oauth` 配置；OAuth 用 SDK 的 `OAuthClientProvider`，客户端信息与 token 存 `data/evolution/mcp-connections/<name>.oauth.json`，回调监听 `http://127.0.0.1:18809/oauth/callback`（一次性），授权页用系统浏览器打开；非交互连接遇 401 抛 `McpNeedsAuthError`，状态 `needs_auth`。新增 `connectOne / disconnect / getServerState / getServerTools`。

**插件 ↔ MCP**（`hub.ts` + `standalone.ts`）：安装后按插件声明连接（交互式，可触发 OAuth）；启动时静默重连；卸载时断开并注销工具；MCP 配置热重载后 `reconnectInstalledMcp()`。工具名前缀 `mcp_<server>_<tool>`，技能目录提示词里说明了映射。WS：`plugin.hub.mcp.connect`、`plugin.hub.mcp.configure`（按服务器覆盖 url/oauth，存于 meta `mcpOverrides`）。插件页显示每个服务器的状态芯片（已连接/需要授权/失败）、地址输入框、「应用地址 / 恢复默认 / 授权并连接 / 重新连接」。

**Figma 实测结论**：远程 `https://mcp.figma.com/mcp` 的动态客户端注册按 `client_name` 白名单放行（"Claude Code"、"Cursor" 返回 200，"OpenFlux" 返回 403 "Forbidden"），官方文档明说"只有 Figma MCP Catalog 里的客户端能连接，新客户端需申请 waitlist"（申请表：https://form.asana.com/?k=kBG-ejRQTdY8x_H6a4vM3Q&d=10497086658021 ）。没有冒用白名单名称。可用路径：Figma 桌面版的本地 MCP 服务器 `http://127.0.0.1:3845/mcp`（无需 OAuth），已把 figma 插件的覆盖地址预设为它；用户在 Figma 桌面版 Dev Mode 里开启 "Enable local MCP server" 后点「重新连接」即可。本机装了 Figma 桌面版但未开启该服务，因此本地路径尚未真机验证到工具列表。

**本地 MCP 自动重连（2026-09-14）**：`PluginHub.startMcpAutoReconnect()` 每 30s 扫描已安装插件，只对处于 error/disconnected 且地址是回环（127.0.0.1 / localhost / [::1]）或 stdio 的服务器静默重试，远程被拒的服务器不会被反复打。插件页打开时每 15s 轮询一次状态，所以 Figma 桌面版一开、本地 3845 起来后，卡片会自己变绿。验证方式：用 SDK 起一个假的本地 Streamable HTTP 服务器（scratchpad/fake-figma-mcp.mjs）先关后开，观察状态从"连不上"变为"已连接（2 个工具）"。
